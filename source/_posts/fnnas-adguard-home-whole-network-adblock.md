浏览器装个去广告插件，只能管住这一个浏览器。电视开机广告、App 开屏、智能音箱和摄像头在后台悄悄请求的追踪域名，压根没地方装插件。

换个思路就通了：**所有设备上网前都得先问一句「这个域名的 IP 是多少」**。把这一问统一接到自己家里的一台 DNS 服务器上，广告域名直接回一个空结果，设备连广告服务器都找不到，自然就没广告了。设备端不用装任何东西，改一次路由器，全家生效。

这篇记录的就是在飞牛 NAS 上把 [AdGuard Home](https://github.com/AdguardTeam/AdGuardHome) 跑起来、并且让**所有设备真的都走它**的完整过程。重点不在装，而在后半段那些「看着配好了、其实被悄悄绕过」的坑。

<!-- more -->

## 一、先搞清楚它能拦什么、拦不了什么

AdGuard Home 是一个网络级 DNS 过滤器。设备把域名查询发给它，它按规则表判断：正常域名转发给上游 DNS，广告、追踪、恶意域名直接返回空结果，同时把每次查询记进日志。

正因为工作在 DNS 这一层，它覆盖得了所有联网设备，但也天生有边界：

| 能拦 | 拦不了 |
|---|---|
| 独立的广告域名、统计追踪域名 | 和正片内容走同一个域名的广告（如部分视频平台贴片、信息流广告） |
| App 开屏、电视开机广告的请求域名 | 网页里的广告位元素、弹窗（得靠浏览器插件按页面结构处理） |
| 恶意、钓鱼域名 | 已经写进 App 代码里的图片广告 |
| 智能设备后台那些莫名其妙的请求 | 设备连的是移动数据、不在家里 Wi-Fi 下 |

{% note info %}
装好之后仪表盘上的拦截率通常在 **20%～30%**，这是正常值，不是没配好。别一上来就追求「拦截 99%」，规则加得越猛，误杀越多，最后家里人刷不了视频、打不开小程序，还得回头一条条捞。先跑稳，再慢慢加。
{% endnote %}

一句话定位：**它是全家网络的一层基础防护，不是浏览器广告插件的替代品**。两个一起用，效果最好。

## 二、为什么放在飞牛 NAS 上

AdGuard Home 要长期在线，还得有个内网固定地址。飞牛刚好三条都占：全年开机、内网 IP 固定、自带 Docker，x86 性能跑几万条规则毫无压力。

| 部署位置 | 推荐度 | 说明 |
|---|---|---|
| NAS（飞牛、群晖等） | ★★★★★ | 常年开机、有 Docker、内网地址稳定，最省事 |
| 软路由 / 旁路由 | ★★★★★ | 网络入口和 DNS 放一起，最理想，但要多一台设备 |
| 树莓派、闲置小主机 | ★★★★☆ | 功耗低，适合专门跑这个 |
| 普通台式机 | ★★☆☆☆ | 能体验，但一关机全家 DNS 就断 |
| 公网服务器 | ★★☆☆☆ | 不建议新手直接开放 53 端口，安全配置要求高 |

有个前提得先认：DNS 是基础服务，**NAS 一重启或容器一挂，全家就会变成「Wi-Fi 连着、网页打不开」**。第十节给兜底办法，别跳过。

## 三、部署：用 Docker Compose

飞牛有两条路：应用商店里搜 AdGuardHome 一键安装，或者用 Docker Compose。**推荐 Compose**——镜像版本自己控、`conf` 和 `work` 两个目录挂在容器外，以后升级、换机器、备份配置都不慌。应用商店胜在省事，但版本和端口由镜像决定，出问题不好排查。

### 先查 53 端口有没有被占

DNS 服务固定要 53 端口，宿主机上要是已经跑着 `dnsmasq`、`systemd-resolved` 之类，容器会直接起不来。SSH 进飞牛查一下：

```bash
sudo ss -tulnp | grep :53
```

**没有输出就踏实了**，飞牛一般是空的。万一被占，优先停掉占用服务抢回 53；实在不行再改用 5335 这类非常规端口，但那样路由器下发 DNS 时写法麻烦，能抢回就抢回。

### 编排文件

在飞牛 Docker 里新建 Compose 项目，路径选「我的文件」下一个空文件夹，贴进去：

```yaml
services:
  adguardhome:
    image: adguard/adguardhome:latest
    container_name: adguardhome
    restart: unless-stopped
    environment:
      - TZ=Asia/Shanghai
    ports:
      - "53:53/tcp"
      - "53:53/udp"
      - "3000:3000/tcp"
    volumes:
      - ./work:/opt/adguardhome/work
      - ./conf:/opt/adguardhome/conf
```

几个参数说清楚，免得照抄踩坑：

| 配置 | 作用 | 容易错的地方 |
|---|---|---|
| `53:53/tcp` + `53:53/udp` | DNS 本体 | **两条都要**。查询走 UDP，但响应超长、部分场景会切 TCP，漏一条就时好时坏 |
| `3000:3000/tcp` | 首次安装向导 + 日常管理后台 | 容器内固定 3000；若飞牛上 3000 被占，改左边即可（如 `3001:3000`），右边别动 |
| `./work` | 统计数据、查询日志 | 挂出来才有历史，否则删容器就全没 |
| `./conf` | 配置、账号、数据库 | **最重要的目录**，备份它就等于备份整套设置 |
| `restart: unless-stopped` | NAS 重启后自己爬起来 | 它瘫了全家上不了网，这条必须有 |

{% note info %}
论坛里常见另一种做法：勾选 **host 网络模式**，这样连端口映射都省了。能用，但日志里容易冒出一堆 IPv6 客户端、不好区分是哪台设备。新手建议按上面的 bridge + 端口映射来，行为更可预期。
{% endnote %}

启动：

```bash
docker compose up -d
```

## 四、初始化向导

浏览器打开 `http://飞牛内网IP:3000`，四步走完：

| 步骤 | 怎么填 |
|---|---|
| 管理界面监听 | 选所有接口，端口保持 3000 |
| DNS 服务监听 | 端口 53；**监听地址选飞牛的内网 IP**，不要选 `127.0.0.1` |
| 管理员账号 | 自己设用户名密码，记牢 |
| 完成 | 自动跳转管理后台，登录进仪表盘 |

监听地址这里有个小细节：选 `0.0.0.0` 也行，但日志里容易多出一堆 IPv6 客户端，后面排查时看不清哪台是哪台；直接指定飞牛的内网 IPv4 地址最清爽。而选了 `127.0.0.1`，别的设备根本连不上，是新手最常踩的一脚。

## 五、配上游 DNS

进「设置 → DNS 设置 → 上游 DNS 服务器」。AdGuard Home 拦完广告之后，剩下的正常域名还得有人去解析，这就是上游。

国内家庭宽带建议 **2～3 个就够**，别一口气填十几个：

```text
https://dns.alidns.com/dns-query
https://doh.pub/dns-query
223.5.5.5
```

| 项 | 建议 |
|---|---|
| 上游 | 一两个国内 DoH 保证国内站点解析顺畅，再留一个纯 IP 的明文 DNS 兜底速度 |
| Bootstrap DNS | **必须填纯 IP**（如 `223.5.5.5`）。DoH 那个域名本身也得先解析出来，填域名会自己把自己绕死 |
| 并行请求 | 可以打开，取最快返回 |
| EDNS 客户端子网 | 建议打开，CDN 调度更准，视频和下载不容易绕远路 |

填完先点「测试上游」，全绿再应用。

{% note warning %}
上游全填境外 DoH、Bootstrap 又只给了境外 DNS，是最典型的「配置保存了但全网解析失败」组合。
{% endnote %}

## 六、过滤规则：中文环境的关键一步

「过滤器 → DNS 封锁清单 → 添加阻止清单」。默认勾着的 `AdGuard DNS filter` 是官方通用规则，对英文广告管用，**对国内 App 和电视开机广告覆盖得很稀**。头一天没加中文规则就以为装错了，是很常见的误会。

中文环境补一条 anti-AD 就够了：

```text
https://anti-ad.net/easylist.txt
```

{% note warning %}
**这里有个很多教程都写反的坑**：anti-AD 提供两个文件，`easylist.txt` 和 `adguard.txt`。给 **AdGuard Home** 用的是 **`easylist.txt`**，不是名字看起来更对口的 `adguard.txt`。

两个文件的头部注释写得很直白：`easylist.txt` 里是 `This list only applies to AdGuard Home`；`adguard.txt` 里是 `If you are using AdGuard Home, please load easylist.txt`。后者是给 AdGuard 浏览器插件这类能匹配完整 URL 的工具用的，包含 URL 路径规则，塞进 DNS 过滤器里轻则规则不生效，重则误杀。

照着填之前自己 `curl` 一下文件头，几秒钟的事，比事后纳闷「怎么一条都没拦住」划算。
{% endnote %}

规则清单**不是越多越好**：先用默认清单 + anti-AD 跑两三天，看日志再决定要不要加。清单叠太多会拖慢解析、增加误杀，排查起来还互相打架。

## 七、让所有设备生效：改路由器 DNS

装好只保护「主动把 DNS 指向它」的设备。要全家自动生效，核心就一步：

进路由器后台，找 **LAN 口设置 / DHCP 服务**里的 DNS 下发项，把主 DNS 改成飞牛的内网 IP。

| | 主 DNS | 备用 DNS |
|---|---|---|
| ✅ 正确 | 飞牛内网 IP（如 `192.168.1.100`） | **留空** |
| ✅ 有两个节点 | 飞牛内网 IP | 第二个 AdGuard Home 节点 IP |
| ❌ 常见错误 | 飞牛内网 IP | `223.5.5.5` / `119.29.29.29` / `8.8.8.8` |

{% note warning %}
**备用 DNS 千万别顺手填个公共 DNS**。不少设备会在主 DNS 稍慢时直接切到备用，广告就时有时无、日志断断续续，排查半天找不着原因。只有一个节点时，备用留空是最稳的。
{% endnote %}

改完让设备重新拿一次租约：手机开关一次 Wi-Fi、电脑 `ipconfig /release` 再 `renew`，或者干脆重启路由器。

如果路由器（尤其是运营商光猫）**根本不让改 DNS**，还有一招：用 AdGuard Home 自带的 DHCP 服务器（「设置 → DHCP 设置」），把路由器 DHCP 关掉，由它来发地址和 DNS，一步切干净。

{% note danger %}
切 DHCP 之前，**先记下路由器后台地址和登录密码，确认飞牛是固定 IP**。两个 DHCP 同时开会把家里网络搞乱；自己把自己关在门外，就只能重置路由器了。
{% endnote %}

## 八、最容易翻车的地方：设备被悄悄绕过

到这一步，多数设备应该已经走 AdGuard Home 了。但「所有设备」这四个字，真正难的是下面这些绕过路径。它们共同的表现是：**仪表盘有流量、规则也在更新，可某些设备广告照旧**。

| 绕过路径 | 典型现象 | 处理办法 |
|---|---|---|
| 备用 DNS 填了公共 DNS | 过滤时灵时不灵 | 备用留空（见上一节） |
| IPv6 RA / DHCPv6 下发运营商 DNS | 手机、部分 App 广告照旧，IPv4 设备正常 | 路由器关掉 IPv6 DNS 下发；或把 IPv6 DNS 也指向 AdGuard Home 的内网 IPv6 地址 |
| 浏览器「使用安全 DNS」、安卓「私人 DNS」 | 就这一台电脑或手机没效果 | 浏览器里关掉安全 DNS；安卓把私人 DNS 设为「自动」 |
| Apple 私密中转（iCloud Private Relay） | iPhone 上 Safari 广告照旧 | AdGuard Home 会拦截特定域名促使其降级；仍不行就在路由器层处理 |
| 设备写死 `8.8.8.8` / `1.1.1.1`（电视盒子、摄像头、Chromecast） | 查询日志里**根本没有这台设备** | 路由器防火墙把出方向 53 端口做 DNAT 重定向回飞牛 IP，强制抓回来 |
| 全隧道 VPN | 一连 VPN 就完全不过滤 | 改成分流，把 DNS 指回 AdGuard Home |
| 个别 App 自带加密 DNS | 单独某个 App 广告照旧 | 在「过滤器」里启用封锁已知 DoH 服务器，或用清单屏蔽常见 DoH 域名 |

{% note info %}
判断有没有被绕过，**别盯着广告看，去看查询日志**。按设备 IP 筛一下：日志里压根没这台设备的请求，就是没走过来（查 DNS 下发、硬编码、IPv6）；有请求但没被拦，才是规则问题。这两类问题解法完全不同，先分清再动手。
{% endnote %}

## 九、验证与日常排查

三步确认真的生效了：

1. 设备上看 DNS 是不是飞牛 IP。Windows 用 `ipconfig /all`，手机在 Wi-Fi 详情里看。
2. AdGuard Home 仪表盘查询数在涨、查询日志里出现了手机、电视、电脑各自的 IP。
3. 命令行测一下，广告域名返回空、正常域名正常解析：

```bash
nslookup 某个已知广告域名 飞牛内网IP
nslookup www.baidu.com 飞牛内网IP
```

**误杀**是日常最常遇到的事：某个 App 突然打不开、小程序转圈。正确做法是打开查询日志，按设备 IP 和时间筛，找出刚被拦下的域名，点放行或加进白名单，再刷新测试。**不要一出问题就整个关掉过滤**，那等于白装。

两个顺手能提升体验的设置：

- **客户端命名**：「设置 → 客户端设置」里把 `192.168.1.21` 标成「客厅电视」、`192.168.1.22` 标成「孩子的平板」。日志立刻好读，还能给不同设备配不同策略（比如只给孩子设备开严格过滤、禁用成人内容）。
- **DNS 重写**：「过滤器 → DNS 重写」里给内网服务起短名字，比如 `nas.home → 192.168.1.100`、`ha.home → 192.168.1.101`。以后访问 NAS 不用记 IP。

查询日志还有个附带价值：能看出家里哪台设备最「吵」。哪个摄像头半夜在疯狂请求陌生域名、哪个盒子一直在上报数据，看一眼统计就清楚。

## 十、别让全家断网

单点故障必须提前想好，否则 NAS 一次重启就能让全家以为宽带坏了。

| 情况 | 兜底办法 |
|---|---|
| 只有一台设备 | 记住恢复路径：路由器 DNS **临时改回公共 DNS** → 修容器 → 再改回来。把这一步写进备忘录 |
| 有条件加一台 | 软路由、树莓派或小主机上再跑一个节点，路由器备用 DNS 填它（这是唯一推荐填备用 DNS 的场景） |
| NAS 重启 | 编排里的 `restart: unless-stopped` 已经保证容器自启 |
| 换机器 / 重装 | 打包 `conf` 目录即可，账号、规则、客户端配置全在里面；`work` 只是统计和日志，可丢 |

## 十一、小结

整套链路其实很短：**飞牛上跑 AdGuard Home → 配好上游和中文规则 → 路由器把 DNS 下发改成飞牛 IP、备用留空 → 用查询日志逐个确认设备都走了过来**。

难点从来不在装，而在「所有设备」这四个字：IPv6 下发、浏览器安全 DNS、设备硬编码 DNS，任何一条漏了都会让某台设备悄悄绕过去。把第八节那张表对着过一遍，比反复加规则有用得多。

最后还是那句话：DNS 层过滤是基础防护，不是万能药。先轻量跑起来，稳了再慢慢加规则——**家里人能正常看视频、上网、工作，比拦截率多两个百分点重要得多**。
