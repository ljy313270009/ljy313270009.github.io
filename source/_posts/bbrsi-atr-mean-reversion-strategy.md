这是一篇按代码逐行写的拆解，不是按想法写的。

我把一个 4 小时周期的均值回归策略原样跑了一遍回测，范围是**市值前 100 的加密货币**（排除稳定币、黄金代币、股票代币），允许同时开 10 个仓位：**2572 笔交易，总收益 −80.50%，最大回撤 83.76%，胜率 41.1%**。这篇文章干两件事：前半部分把这套逻辑到底在做什么讲清楚——不美化、不补料，代码怎么写就怎么写；后半部分复盘它为什么亏，每一条原因都对应到具体某一行代码，并且都用真实数据做了对照验证。

之所以值得写，是因为**亏的原因几乎全部能在代码里读出来**。如果你只看回测曲线，只会看到一条向下的线；但读代码能知道是哪一步在漏钱，以及该动哪里。

{% note info %}
**关于 −80.50% 这个数字，有一句必须先说**：它是「2020 年 1 月起 + 市值前 100 币种」这个口径下的结果。同一份代码，把时间换成 2024 年起、币池换成过滤后的 54 个币，能跑出 **+14.03%**——差了 94 个点。第七节末尾有完整的拆解，包括每个变量各值多少。先看那一节，再判断这个策略。
{% endnote %}

{% note warning %}
顺带说一句：我原本以为“加趋势过滤”是首选的修复方向。做完对照实测之后这个判断被推翻了——**EMA200 过滤砍掉 96.5% 的信号，胜率却一点没提升**。第九节有完整数据。别跳过那一节。
{% endnote %}

## 一、这套规则在做什么

一句话：**价格跌到布林带下轨、RSI 进超卖并且开始拐头向上时做多，等收盘价回到中轨卖出，中间用「下轨再往下 1.5 个 ATR」兜住风险。**

方向上只做多，不做空；不设止盈比例，出场完全交给信号。

代码里声明的全部参数如下，一个不漏：

| 参数 | 值 | 作用 |
|---|---|---|
| `timeframe` | `4h` | 4 小时一根 K 线 |
| `can_short` | `False` | 只做多 |
| `stoploss` | `-0.08` | 静态止损 −8% |
| `use_custom_stoploss` | `True` | 启用自定义止损 |
| `minimal_roi` | `{"0": 100}` | 相当于关闭，止盈不看比例 |
| `startup_candle_count` | `100` | 预热 K 线数 |
| `process_only_new_candles` | `True` | 只在新 K 线上处理 |
| `bb_period` / `bb_std` | `20` / `2.0` | 布林带周期与标准差倍数 |
| `rsi_period` | `14` | RSI 周期 |
| `rsi_oversold` | `30` | 超卖门槛 |
| `rsi_overbought` | `70` | **定义了但代码里没用到** |
| `atr_period` | `14` | ATR 周期 |
| `atr_stop_mult` | `1.5` | 止损放在下轨下方几个 ATR |
| `min_bandwidth` | `0.015` | 布林带宽度下限过滤 |

{% note info %}
`rsi_overbought = 70` 是个遗留项。因为只做多，没有任何地方读它——砍掉空头之后它就没人用了。留着不影响运行，但读代码时容易误以为空头逻辑还在。
{% endnote %}

## 二、指标怎么算

只算四样东西，全在 `populate_indicators` 里：

```python
bb = ta.BBANDS(dataframe, timeperiod=20, nbdevup=2.0, nbdevdn=2.0)
dataframe["bb_lower"]  = bb["lowerband"]    # 中轨 − 2σ
dataframe["bb_middle"] = bb["middleband"]   # 20 期均线
dataframe["bb_upper"]  = bb["upperband"]    # 中轨 + 2σ

dataframe["bb_width"] = (bb_upper - bb_lower) / bb_middle   # = 4σ / 中轨

dataframe["rsi"]      = ta.RSI(dataframe, timeperiod=14)
dataframe["rsi_prev"] = dataframe["rsi"].shift(1)

dataframe["atr"] = ta.ATR(dataframe, timeperiod=14)
```

三个指标各管一摊，分工是这样的：

| 指标 | 回答的问题 | 在策略里的角色 |
|---|---|---|
| **布林带** | 价格现在处在什么位置 | 定边界：下轨是“便宜”的定义，中轨是“回归目标” |
| **RSI** | 动能往哪边拐 | 定时机：光便宜不够，要等它开始回头 |
| **ATR** | 一根 K 线正常波动多大 | 定容错：止损该放多远 |

`rsi_prev` 这一列是整套入场逻辑里最关键的一列——**它让“超卖”变成了“超卖且拐头”**。`bb_width` 只用于过滤，不参与判断。

## 三、入场：四个条件同时满足

```python
dataframe.loc[
    (
        (dataframe["low"] <= dataframe["bb_lower"])
        & (dataframe["rsi"] < self.rsi_oversold)
        & (dataframe["rsi"] > dataframe["rsi_prev"])
        & (dataframe["bb_width"] >= self.min_bandwidth)
        & (dataframe["volume"] > 0)
    ),
    "enter_long",
] = 1
```

逐条讲它各解决什么问题：

**1. `low <= bb_lower`：用最低价，不用收盘价**

这是有意的。收盘价跌破下轨要求当根 K 线收在极低位置，信号会少很多；用最低价意味着**只要插针碰到下轨就算**。好处是不漏掉那些瞬间砸穿又被拉回来的机会，坏处是信号数量明显变多，质量参差。

**2. `rsi < 30`：确认真的超卖**

价格到位置和动能到位置是两回事。这一条把“碰了下轨”筛成“碰了下轨且动能耗尽”。

**3. `rsi > rsi_prev`：要求拐头**

这是整个策略的灵魂。没有这一条，你会在 RSI 一路下探的过程中连续开仓——每跌一点就买一次，等于主动接飞刀。加了这一条，只在 RSI 从低点抬头的那一根才动手。

{% note warning %}
但要注意，“拐头”的门槛非常低：**只要比上一根高一点就算**。在震荡下行的行情里，RSI 在超卖区反复上下抖动，这个条件会被触发很多次。它不是趋势反转确认，只是“这一根没有继续变坏”。
{% endnote %}

**4. `bb_width >= 0.015`：带宽过滤**

意图是跳过那些布林带收得太窄、没有空间的行情。这个值在实际运行中的效果，第八节会单独说——它基本没起作用。

`volume > 0` 只是排除无成交的死 K 线，没有实际过滤意义。

## 四、出场：只有一个条件

```python
dataframe.loc[
    (
        (dataframe["close"] >= dataframe["bb_middle"])
        & (dataframe["volume"] > 0)
    ),
    "exit_long",
] = 1
```

就这么一条：**收盘价回到中轨就走**。

配合 `minimal_roi = {"0": 100}`，比例止盈等于关掉了，所以这是唯一的主动出场方式。没有最大持仓时间、没有保本退出、没有分批。

目标距离可以算出来：入场价在下轨附近，目标在中轨，两者相距 **2σ**。

## 五、止损：代码里真正的算法

这是整份代码里最值得细看的部分，因为它写出来是三行，跑起来是三层机制叠加。

```python
def custom_stoploss(self, pair, trade, current_time,
                    current_rate, current_profit, after_fill, **kwargs) -> float:
    hard_stop = -0.08
    dataframe, _ = self.dp.get_analyzed_dataframe(pair, self.timeframe)
    if dataframe is None or len(dataframe) < 1:
        return hard_stop

    last = dataframe.iloc[-1]
    stop_price = last["bb_lower"] - self.atr_stop_mult * last["atr"]

    atr_stop_pct = stoploss_from_absolute(
        stop_price,
        current_rate=current_rate,
        is_short=False,
        leverage=trade.leverage,
    )
    return max(atr_stop_pct, hard_stop)
```

表面看是「ATR 止损和 −8% 取更紧的那个」。实际执行路径是这样的：

**第一步：开仓瞬间，先按静态止损挂上**

Freqtrade 在建立交易时会先用 `stoploss` 初始化一次（`backtesting.py`）：

```python
trade.adjust_stop_loss(trade.open_rate, self.strategy.stoploss, initial=True)
```

所以初始止损价 = 入场价 × 0.92。

**第二步：每根 K 线，自定义止损被调用**

调用时传入的 `current_rate` 并不是收盘价。回测里传的是**当根 K 线的最高价**（`interface.py` 中 `current_rate=(bound or current_rate)`，多单的 `bound` 是 `high`）。

**第三步：`stoploss_from_absolute` 的返回值恒为正数**

这是最容易看错的地方。它的源码注释写得很直白：

```python
:return: Positive stop loss value relative to current price
```

也就是说，一个“下方 3%”的止损，它返回的是 `0.03`，不是 `-0.03`。

**第四步：`max()` 这行的实际结果**

```python
return max(atr_stop_pct, hard_stop)   # max(0.03, -0.08) → 0.03
```

因为 `atr_stop_pct` 恒 ≥ 0，而 `hard_stop = -0.08`，**这个 `max()` 永远返回 `atr_stop_pct`**。那句 −8% 兜底在这个比较里一次都赢不了，是死代码。

**第五步：`abs()` 把正数还原成下方止损**

真正转成价格是在 `trade_model.py` 的 `adjust_stop_loss` 里：

```python
new_loss = float(current_price * (1 - abs(stoploss / leverage)))
```

`abs()` 把 `0.03` 还原成“当前价下方 3%”。代入整个链条算下来，新的止损价恰好等于：

```
止损价 = bb_lower − 1.5 × atr
```

跟 `stop_price` 那一行完全一致——绕了一圈，结果是对的。

**第六步：棘轮，只上移不下降**

同一段源码里的判定：

```python
# stop losses only walk up, never down!
if allow_refresh or (higher_stop and not self.is_short) or ...:
```

只有新算出来的止损价**高于**旧止损，才会更新。

{% note danger %}
**把这六步合起来，实际生效的止损是：**

> **止损价 = 布林下轨 − 1.5 × ATR，且只能往上走，永远不会放宽。**

而 −8% 的静态止损只在开仓那一瞬间存在，第一次自定义止损计算就会被更紧的 ATR 止损顶掉（除非 ATR 大到 1.5×ATR 超过 8%，那只有极端行情才会发生）。
{% endnote %}

这里有个直接的后果：**入场价在下轨附近，止损在下轨下方 1.5 个 ATR**。也就是说，你判定“这里已经是极端位置”，却只允许它再极端 1.5 个 ATR。

## 六、一笔交易的完整时间线

把上面所有规则串起来，一笔典型交易长这样：

| 时点 | 发生了什么 | 依据 |
|---|---|---|
| K 线 N | 最低价插到 `bb_lower`，RSI < 30 且比上一根高，带宽达标 | 入场四条件 |
| K 线 N+1 开盘 | **按开盘价成交**（信号 `shift(1)`，见下） | `backtesting.py` |
| 成交瞬间 | 止损先挂在 入场价 × 0.92 | 静态 `stoploss` |
| K 线 N+1 起每根 | 止损重算为 `bb_lower − 1.5×ATR`，只升不降 | `custom_stoploss` |
| 若干根之后 | 收盘价 ≥ `bb_middle` → 信号 | 出场条件 |
| 再下一根开盘 | 按开盘价卖出，目标约 **+2σ** | 同上 |

{% note info %}
信号产生和成交之间隔了一根 K 线，这是 Freqtrade 刻意做的。源码里把信号列 `shift(1)` 之后再使用，注释写的是「To avoid using data from future」。所以信号基于 K 线 N 的收盘数据，成交在 K 线 N+1 的开盘价。
{% endnote %}

## 七、回测结果

先说环境：Freqtrade 2026.9，币安现货，4 小时周期，2020-01-17 到 2026-10-01，手续费按 0.1% 单边计，**最多同时持仓 10 笔**。

币种不是随手挑的几个主流币，而是按下面的规则筛出来的：

1. 从 CoinGecko 取当前市值排名前 250；
2. 剔除 **稳定币**、**黄金类代币**（PAXG / XAUT 等）、**股票类代币**（AAPLx / TSLAx 这类代币化股票）——这三个分类的成员名单也取自 CoinGecko，另加了一层关键词兜底；
3. 跟币安现货的 USDT 交易对取交集，剔掉没上架的（XMR、OKB、CRO、LEO、MNT 这些都被剔掉了）；
4. 取剩下的前 100 名。

最终 100 个币对，市值从第 1 名 BTC 到第 100 名 S（约 1.8 亿美元）。

| 指标 | 结果 |
|---|---|
| 总收益率 | **−80.50%**（−24151.1 USDT） |
| 年化（CAGR） | −21.63% |
| 交易笔数 | 2572 |
| 胜率 | **41.1%**（1058 赢 / 1514 亏） |
| 平均单笔 | −0.52% |
| 平均盈利 / 平均亏损 | +5.91% / −5.01% |
| 盈亏比 | 1.18 : 1 |
| **盈亏平衡所需胜率** | **45.9%** |
| 最大回撤 | **83.76%**（25868.1 USDT），持续 1789 天 |
| 利润因子 | 0.74 |
| 期望值 | −9.39（−0.15R） |
| Sharpe / Sortino / Calmar | −1.86 / −2.53 / −0.75 |
| SQN | −4.69 |
| 平均持仓时长 | 盈利 38.8 小时 / 亏损 18.1 小时 |
| 同期市场涨幅 | +205.03% |

同期市场涨了两倍，这套规则亏掉八成。**回撤 83.76% 且持续近五年**，意味着它从 2020 年 2 月开亏之后，账户几乎再没回到过起点。

{% note warning %}
**这组数据有个先天缺陷，得先讲清楚**：币种是按**今天**的市值排名选的，而回测从 2020 年开始。2020 年时这些币里有很多还没上市，或者当时排名远在 100 名开外。这叫**幸存者偏差**，会让结果偏乐观。

也就是说，**真实表现只会比这个 −80.5% 更差，不会更好。**
{% endnote %}

### 关键的一张表：出场方式

把 2572 笔交易按出场原因拆开，问题立刻就清楚了：

| 出场方式 | 笔数 | 占比 | 胜率 | 总盈亏 |
|---|---|---|---|---|
| **止损** | 1440 | 56.0% | **0%** | **−91108 USDT** |
| **信号（回到中轨）** | 1109 | 43.1% | **95.4%** | **+68823 USDT** |
| 棘轮止损 | 23 | 0.9% | 0% | −1866 USDT |

**凡是走到中轨的，95.4% 都是赚的；凡是被止损的，全是亏的。**策略不是不会赚钱——它那 1109 笔正常出场赚了 6.9 万——而是被 1440 笔止损全部吃回去还倒贴 2.2 万。

这也顺带印证了第五节那个棘轮：那 23 笔 `trailing_stop_loss` 就是止损被顶上去之后触发的，说明单向收紧确实在运行。

### 分年度

| 年份 | 笔数 | 胜率 | 平均单笔 | 总盈亏 |
|---|---|---|---|---|
| 2020 | 202 | 37.6% | −1.00% | −6111 |
| 2021 | 243 | 41.2% | −0.63% | −5640 |
| 2022 | 450 | 41.3% | −0.80% | −6230 |
| 2023 | 359 | 37.6% | −0.68% | −2717 |

七年里只有最后两年勉强打平。**2024 年最差**（487 笔，胜率 33.3%），2022 年交易量最大也亏得最多——那正是单边下跌的一年，信号在下跌中反复触发，正好印证第八节第 2 条。

### 币种数和仓位数，各自贡献了多少

上一版我用的是 8 个币对 + 3 个仓位。这次两个变量同时改了，所以我跑了完整的 2×2 对照，把两个因素拆开：

| 币种数 | 最大持仓 | 笔数 | 胜率 | 平均单笔 | 总收益率 |
|---|---|---|---|---|---|
| 8 | 3 | 457 | 39.8% | −0.66% | −70.57% |
| 8 | **10** | 578 | 42.2% | −0.44% | **−25.41%** |
| **100** | 3 | 1353 | 37.0% | −1.00% | **−99.35%** |
| **100** | **10** | 2572 | 41.1% | −0.52% | −80.50% |

结论是**两个变量方向相反**：

- **放宽仓位是改善**。同样 8 个币，3 仓位 → 10 仓位，收益从 −70.57% 变成 −25.41%；同样 100 个币，从 −99.35% 变成 −80.50%。原因是每笔占用的资金从 1 万降到 3 千，分散之后单笔亏损对账户的冲击小了。
- **扩大到 100 个币是恶化**。同样 3 仓位，−70.57% → −99.35%；同样 10 仓位，−25.41% → −80.50%。

但要注意，**扩大币种带来的恶化，主要不是因为小币的信号更差，而是因为交易机会变多了**——同一个负期望值被执行了 5.7 倍（457 笔 → 2572 笔），自然亏得更多。

### 信号质量跟市值排名无关

如果小币种是拖累，那按市值分段应该能看出梯度。实际结果：

| 市值排名 | 币数 | 笔数 | 胜率 | 平均单笔 | 总盈亏 |
|---|---|---|---|---|---|
| 1–20 | 18 | 1036 | 40.5% | −0.51% | −14222 |
| 21–40 | 20 | 438 | 42.5% | −0.49% | −2864 |
| 41–60 | 19 | 396 | 39.4% | −0.60% | −2874 |
| 61–80 | 20 | 393 | 40.5% | −0.42% | −1444 |
| 81–100 | 20 | 309 | 44.3% | −0.60% | −2746 |

**五档全是负的，胜率都在 39%~44% 之间，没有梯度。**倒数第一档（81–100 名）的胜率 44.3% 甚至是五档里最高的。

这说明问题不在选币——**这套规则在任何一个市值区间都没有 edge**。前 20 名之所以总亏损最大（−14222），只是因为它们交易笔数最多（1036 笔）。

单币层面也一样：亏得最多的全是主流大币（ETH −2273、DOGE −2160、BNB −1852、LINK −1845、BTC −988），赚得最多的是 CAKE、TWT、RAY 这些小币——但前者做了 60~80 笔，后者只做了 18~40 笔。**亏损基本上就等于「负的期望值 × 交易笔数」。**

### 换口径，数字能变多少

同一份代码，我在另一台机器上跑出过 **+113%**；在这台机器上，本文基准是 **−80.50%**。差异一个都不来自代码，全部来自口径。把这五个变量一个个拆开测，结果如下（统一 10 个并发仓位、1 倍杠杆、4 小时周期、起始资金 1000 USDT）：

| 口径 | 时间区间 | 数据源 | 币池 | 手续费 | 笔数 | 总收益 | 同期市场 |
|---|---|---|---|---|---|---|---|
| **本文基准** | 2020-01 起 | 现货 | 100 | 0.1% | 2572 | **−80.50%** | +205.03% |
| 只改时间区间 | 2024-01 起 | 现货 | 100 | 0.05% | 1351 | **−25.55%** | +24.96% |
| 再改币池 | 2024-01 起 | 现货 | 54 | 0.05% | 766 | **+14.03%** | +77.63% |
| 再改数据源 | 2024-01 起 | **永续** | 51 | 0.05% | 940 | **−3.71%** | +72.77% |
| 永续 + 宽止损 3×ATR | 2024-01 起 | 永续 | 51 | 0.05% | 732 | **+18.60%** | +72.77% |
| 永续 + 零手续费 | 2024-01 起 | 永续 | 51 | 0 | 940 | **+5.71%** | +72.77% |
| 现货 + 关掉止损 | 2024-01 起 | 现货 | 54 | 0.05% | 566 | **+45.14%** | +77.63% |

**1. 时间区间是最大的一项，值 55 个点。**同样 100 个币，2020 起是 −80.50%，2024 起是 −25.55%。原因就在上面那张分年度表：2020 到 2023 这四年每年都是负的，2022 年单边下跌时最惨。只做多的抄底逻辑，起点放在熊市里，等于先让它输四年。

**2. 币池第二大，而且它不是线性叠加的。**100 个币是 −25.55%，换成过滤后的 54 个币是 +14.03%。但更有意思的是：把这 100 个拆成「54 个」和「剩下 46 个」分别跑，结果是 +14.03% 和 −0.81%；合起来跑却是 −25.55%，**比两边都差**。原因是 **10 个仓位是稀缺资源**——基准那次有 1233 笔入场信号因为仓位满了被拒绝，垃圾币的信号会把好币的信号挤掉。所以「多加几个币」不是中性操作，它会改变哪些信号最终成交。

**3. 现货换永续，是变差的。**同样 51 个币，现货 +12.56%，永续 −3.71%，差 16 个点。而且这还没算资金费率——真算上，多头要付资金费，只会更差。

**4. 手续费一项就值 9 个点。**同样 940 笔，双边 0.05% 是 −3.71%，零手续费是 +5.71%。第八节第 5 条说这套规则对成本极度敏感，这就是数字。

**5. 起始资金不影响百分比收益。**同样 51 个币，起始 1000 USDT 和 3 万 USDT 跑出来都是 +12.56%——因为每笔金额等于可用资金除以仓位数，整体按比例缩放。所以「用 1000 还是 3 万」不是对账项，不用纠结。

{% note danger %}
**换口径能把它从 −80% 变成 +14%，但改变不了结论。**

看表格最后一列：**同期市场涨了 72.77% 到 77.63%**。在最宽容的口径下（2024 年起 + 过滤后的 54 个币 + 现货），这套规则赚 14.03%，年化 4.76%；而什么都不做、买入持有赚 77.63%，年化 22% 上下。

所以那个 +14% 不是反转的证据，它只是换了个方式证明同一件事：**这套规则没有 edge。它赚的那部分是市场给的，而且只拿到了市场的零头。**
{% endnote %}

给同一套代码做跨机器对账，至少要对齐这五项：**时间区间、币池清单、数据源（现货还是永续）、手续费、并发仓位数**。少对齐任何一项，两边的数字就没有可比性——差出 100 个点都不奇怪。

## 八、为什么会亏：七个原因

| # | 原因 | 对应代码 | 后果 |
|---|---|---|---|
| 1 | 止损太紧，且锚在错误的参照物上 | `bb_lower - 1.5 * atr` | 趋势市里一根 K 线就扫掉 |
| 2 | 没有任何趋势过滤 | 入场条件里无方向判断 | 下跌趋势中反复接飞刀 |
| 3 | 目标在趋势市里根本到不了 | `close >= bb_middle` | 止损成了唯一出场方式 |
| 4 | 带宽过滤形同虚设，方向还反了 | `bb_width >= 0.015` | 波动越大越容易进场 |
| 5 | 信号与成交隔一根 K 线 | `shift(1)` | 成本占比过高 |
| 6 | 盈亏比只有 1 出头 | 目标 2σ vs 止损 1.5×ATR | 容错极低 |
| 7 | 棘轮 + 止损锚定下轨 | 只升不降 | 回踩第二只脚常被扫 |

### 1. 止损太紧，锚错了参照物

止损价 = 下轨 − 1.5×ATR，而入场价就在下轨。这意味着：**入场后，价格只要再往下走 1.5 个 ATR 就出局**。

问题在于，下轨本来就是统计意义上的极端位置，而价格一旦真的走出趋势，超过 1.5 个 ATR 是常态不是意外。这套规则一边用“极端”定义入场，一边用“再极端一点点”定义认输，两者是矛盾的。

### 2. 没有趋势过滤

入场条件里没有任何一句判断大方向。四个条件全部是“当前这一根长什么样”，没有一句是“现在是什么行情”。

在持续下跌里，RSI 会在 30 以下待上几十根 K 线，期间 `rsi > rsi_prev` 的“拐头”会反复出现——每一次抖动都是一次入场，每一次入场都撞上 1.5×ATR 的止损。这种连败不是运气差，是规则本身决定的。

### 3. 目标位在下跌趋势里到不了

出场只有 `close >= bb_middle` 这一条。上涨和震荡市里它很自然；但下跌趋势中，价格长期运行在中轨**下方**，中轨本身也在往下走——虽然目标在变低，可价格追不上。

结果就是：**在最容易亏钱的行情里，主动出场这条路是断的，唯一的出口是止损。**

### 4. 带宽过滤几乎不起作用，而且方向是反的

`bb_width = 4σ / 中轨`。4 小时周期下，主流币的典型带宽远大于 `0.015`（常见量级是它的好几倍），所以这个过滤**几乎从来不触发**，等于没写。

更麻烦的是它的方向：它是**下限**过滤——带宽越大越容易通过。而带宽最大的时候，恰恰是急速下跌和崩盘的时候。本该躲开的行情，它一个都没拦住；本该保留的平静行情，它也没加分。

{% note warning %}
想要过滤效果，方向应该是**上限**：带宽超过某个分位（比如近一年的 80 分位）就不做，把极端波动的行情挡在外面。或者干脆先删掉，把带宽当成一个待研究的变量，而不是一个已经调好的参数。
{% endnote %}

### 5. 信号到成交的落差，占比太高

信号基于 K 线 N 的收盘，成交在 K 线 N+1 的开盘。4 小时周期下，一根 K 线的跳空常见在 1%~2%。

而这套策略单笔目标只有 2σ，量级大约 3%。**一次跳空就能吃掉三分之二的目标。**这不是 bug，是系统成本，但对一个目标只有 3% 的策略来说，它是致命比例。

### 6. 盈亏比只有 1 出头

把数字摆在一起看：

- 目标 = 中轨 − 下轨 = **2σ**
- 止损 = 下轨往下 **1.5 × ATR**

σ（20 期标准差）和 ATR（14 期真实波幅均值）都是“一根 K 线典型波动幅度”的度量，量级相近，所以盈亏比理论上就在 1 附近。

实测印证了这一点：**平均盈利 +5.91%，平均亏损 −5.01%，盈亏比 1.18 : 1**。

按这个盈亏比反推，盈亏平衡需要 **45.9% 的胜率**。而实际胜率只有 **41.1%**——差了 4.8 个百分点。2572 笔样本下这个差距不是运气问题，平均单笔 −0.52% 的期望值稳定为负。

而上面第 1、2、3 条，全都在拉低这个胜率。

### 7. 棘轮让第二只脚很难活下来

止损锚在 `bb_lower − 1.5×ATR`，而下轨是滚动的 20 期窗口。入场后如果价格先反弹再回踩，下轨往往已经抬高，止损也被顶上去了。

**同一段回踩深度，第一次能扛住，第二次就被扫。**而双底、回踩确认恰恰是均值回归最常见的形态。这个机制会系统性地把“本该等到中轨”的单子提前砍掉。

## 九、改了三处，实测结果

上面七条是读代码推出来的。推论对不对，得跑一遍才知道。在 100 个币对 + 10 仓位的设定下，我做了三个改法，各跑一次完整回测：

| 版本 | 改动 | 笔数 | 胜率 | 平均盈利 | 平均亏损 | 盈亏比 | 平衡胜率 | 止损出场 | 总盈亏 | 总收益率 |
|---|---|---|---|---|---|---|---|---|---|---|
| 基准 | 原样 | 2572 | 41.1% | +5.91% | −5.01% | 1.18 | 45.9% | 56.0% | **−24151** | −80.50% |
| 宽止损 | `atr_stop_mult` 1.5 → 3.0 | 1994 | **58.1%** | +5.23% | **−7.92%** | **0.66** | 60.2% | 30.5% | −19011 | −63.37% |
| 趋势过滤 | 加 `close > EMA200` | 89 | 40.4% | +6.88% | −6.21% | 1.11 | 47.5% | 58.4% | −2568 | −8.56% |
| 两者都加 | 3.0 + EMA200 | 81 | 58.0% | +5.91% | −7.08% | 0.83 | 54.5% | 24.7% | **+971** | +3.24% |

### 止损宽度是个跷跷板

这是本次实测最有价值的一条。

把止损从 1.5×ATR 放宽到 3×ATR，**胜率从 41.1% 涨到 58.1%**，止损出场占比从 56.0% 降到 30.5%——看起来是全面改善。

但平均亏损同时从 −5.01% 扩大到 **−7.92%**，盈亏比从 1.18 掉到 **0.66**，盈亏平衡所需胜率反而从 45.9% 抬到了 **60.2%**。

缺口只是从 4.8 个百分点缩到 2.1 个百分点。**总收益从 −80.50% 变成 −63.37%，还是亏六成。**

{% note danger %}
**结论：这套策略的问题不在止损宽度。**

放宽止损换来的是「赢的次数变多，但每次输得更狠」。两端同时放大，期望值原地踏步。想靠调这一个参数救回来，是不可能的。
{% endnote %}

### 趋势过滤没起到作用

我原本把趋势过滤排在第一优先级，实测**打脸了**。

加 `close > EMA200` 之后，交易笔数从 2572 掉到 **89**——砍掉 96.5%。问题是**胜率没提升**：40.4%，跟基准的 41.1% 基本一样。

原因不难想：4 小时周期下，价格跌到布林下轨、RSI 进超卖的时候，它通常早就跌破 EMA200 了。**这两个条件本身就互斥**，同时满足的机会极少。所以这个过滤不是“筛掉坏信号”，而是“几乎把所有信号都筛掉了”。

{% note warning %}
**趋势过滤的方向是对的，但 EMA200 这把刀太狠。**要用的话，该换成描述“当前是不是趋势市”的指标（如 ADX 阈值），而不是“价格在长期均线上方”这种硬门槛。
{% endnote %}

### 那个 +971 不能当真

“趋势过滤 + 宽止损”是四组里唯一为正的（+3.24%，回撤 5.97%）。但**只有 81 笔交易**，分摊到 100 个币、六年半，平均每个币一年做 0.12 笔。

81 笔样本算出 58.0% 的胜率，标准误约 ±5.5 个百分点；更关键的是它那 24.7% 的止损出场率和基准的 56.0% 差了整整一倍——这个差异更可能来自样本，而不是策略真的变好了。它唯一能说明的是：**把交易频率压到极低之后，亏损确实变小了**——但这跟“策略有效”是两回事。

{% note info %}
**顺带一个观察**：三个改法里，唯一能持续降低亏损的是**减少交易次数**（基准 2572 笔亏 2.4 万，趋势过滤 89 笔只亏 2568）。这恰恰是最不利的证据——**一个策略如果做得越少亏得越少，说明它每做一笔都在漏钱。**
{% endnote %}

## 十、所以到底该动哪里

实测之后，优先级要重排：

| 优先级 | 改什么 | 实测依据 |
|---|---|---|
| **1** | **重新设计入场信号** | 宽止损把胜率提到 58.1% 仍亏六成，说明信号缺的不是容错，是 edge |
| **2** | 换趋势过滤的指标（ADX 之类），别用 EMA200 | EMA200 砍掉 96.5% 信号且胜率没提升（40.4% vs 41.1%） |
| **3** | 止损维持 1.5×ATR 附近，别往宽调 | 3×ATR 使盈亏比从 1.18 掉到 0.66 |
| **4** | 修掉 `max(atr_stop_pct, hard_stop)` 那行 | 结果碰巧对，但语义是错的 |
| **5** | 带宽过滤改成上限，或先删掉 | 第 4 条，当前几乎不起作用 |

{% note danger %}
**有一条实测结论值得单独记下来：不要指望靠扩大币种池来救这个策略。**

从 8 个币扩大到市值前 100，五个市值档位的胜率全部落在 39%~44% 区间，**没有任何梯度**。均值回归在小市值币上并没有更好，也没有更差——它只是把同一个负期望值复制了更多份。

真正能改善的只有两件事：**让入场信号本身有 edge**，或者**降低交易频率**。
{% endnote %}

{% note info %}
**一个更实际的判断**：如果目标是 4 小时周期上的均值回归，单笔目标只有 2σ（约 3%~5%）的话，它对**手续费和跳空**的敏感度是致命的。要么把周期拉长到日线级别、让单笔目标变大，要么就得接受这是一个对执行成本极度敏感的策略。
{% endnote %}

关于第 4 条，正确的写法是用官方提供的 `stoploss_from_open`——按**入场价**而不是当前价算，语义和代码意图才一致：

```python
from freqtrade.strategy import stoploss_from_open

# 相对入场价的固定百分比止损
return stoploss_from_open(-0.08, current_profit, is_short=False, leverage=trade.leverage)
```

另外可以加一个时间出口：用 `custom_exit` 配合 `trade.open_date` 和 `current_time` 算持仓天数，超过 N 天强制平仓。基准回测里 265 笔止损出场的平均持仓只有 17.5 小时，而盈利单平均 41 小时——**亏的走得快、赚的拿得久**，给深套的单子加个上限不会有坏处。

## 十一、跑之前要确认三件事

**1. 文件名必须和类名一致。** 类叫 `BollingerRsiAtrMeanReversion`，文件就得叫 `BollingerRsiAtrMeanReversion.py`。Freqtrade 是按类名加载策略的，文件名对不上会直接报 `Impossible to load Strategy`。

**2. 确认手续费。** 均值回归单笔只赚 2σ 左右，量级 3%。手续费不设成真实值，回测结果没有任何参考价值。

**3. 想清楚跑现货还是合约。** 这份代码没有声明杠杆，默认是现货——对它只做多的设计来说其实更自洽。要跑合约，必须显式锁 1 倍，否则会用交易所的默认值（多数是 20 倍），−8% 折算过来等于价格跌 0.4% 就扫损。

另外这类策略需要 7×24 挂着跑，机器得一直在线。用云服务器最省事，服务器和域名都可以 [点此注册腾讯云](https://curl.qcloud.com/lxNLjrln) 一站搞定。

## 十二、最后

这套规则写得并不糙。三个指标分工清楚，`rsi > rsi_prev` 那一条说明作者知道“光便宜不够，要等拐头”，用 `low` 而不是 `close` 也说明想过信号密度的问题。

但在 100 个币种、2572 笔交易跑下来，结论很硬：**−80.50%，最大回撤 83.76%，七个年度里只有最后两年勉强打平。**

而且它不是“差一点点”。盈亏平衡需要 45.9% 的胜率，实际 41.1%，差 4.8 个百分点——这个缺口靠调参数补不上。放宽止损能把胜率提到 58.1%，但每笔亏损同步扩大，盈亏比掉到 0.66，平衡线反而抬到 60.2%，等于白忙。

真正的问题在入场那一端：**信号本身没有区分度**。它把“跌到下轨”和“跌到下轨且会回来”当成了同一件事，而这两件事在趋势市里是完全相反的。

{% note success %}
**这次复盘给我的四条教训**

一、**先看出场原因分布，再看总收益。**总收益是一个结果，而出场原因告诉你这个结果是怎么来的。基准里 1440 笔止损、1109 笔信号出场，后者胜率 95.4%——光看 −80.50% 永远发现不了这个结构。

二、**胜率和盈亏比是跷跷板，别只盯着一头。**宽止损把胜率提了 17 个百分点，看起来大获全胜，实际总收益只从 −80.50% 变到 −63.37%。

三、**扩大币种池救不了没有 edge 的信号。**五个市值档位的胜率全在 39%~44% 之间，没有梯度。它只会把同一个负期望值复制更多份。

四、**样本量太小的“改进”是幻觉。**81 笔交易跑出来的正收益，误差范围比收益本身还大，不能当作策略有效的证据。

五、**回测数字必须带上口径，否则没有意义。**同一份代码，换个时间区间和币池能从 −80.50% 变成 +14.03%，差 94 个点；跨机器对账时差出 100 个点也不奇怪。时间区间、币池清单、数据源、手续费、并发仓位数——这五项不对齐，两边的数字说的根本不是同一件事。
{% endnote %}
