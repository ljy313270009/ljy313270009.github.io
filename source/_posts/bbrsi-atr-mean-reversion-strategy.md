手上有三个能跑的指标，拼在一起就能变成策略吗？多数时候不能。

问题不在指标本身，而在于**你没想清楚每个指标各自负责什么**。布林带、RSI、ATR 是三件不同的工具：一个告诉你价格在哪，一个告诉你动能往哪拐，一个告诉你波动有多大。把它们当成三个并列的“买入信号”来叠加，得到的是一堆互相矛盾的条件；把它们当成一条流水线上的三道工序，才能得到一套能讲清楚逻辑的规则。

这篇拆的是一个 4 小时周期的均值回归策略，全部代码不到 150 行。前半部分讲规则：三个指标各管哪一摊，四个入场条件各解决什么问题。后半部分是重点——**同样的规则写成 Freqtrade 代码跑起来，跟你在图上看到的往往不是一回事**。里面有四个陷阱，都是读代码才能发现、看回测曲线看不出来的。

## 一、先说结论

| 项目 | 内容 |
|---|---|
| 策略类型 | 均值回归 / 区间交易 |
| 周期 | 4 小时 |
| 方向 | 只做多 |
| 杠杆 | 现货模式不需要；合约模式必须锁 1 倍 |
| 适用行情 | 震荡市 |
| 必然失效的行情 | 单边趋势，尤其是跌势 |
| 单笔目标 | 下轨 → 中轨，约 1 个标准差 |
| 保护机制 | 入场价 −8% 硬底线 + ATR 止损收紧 |

**这套策略不适合拿来当主策略**。它是震荡市里的小额收益来源，真实价值在于结构清晰，适合当模板理解均值回归这类策略的风控该怎么搭。

## 二、均值回归在赚什么钱

一句话：**价格离开均值之后，大概率会回来。**

20 周期均线代表过去这段时间市场的平均成本。价格跑到均线下方两个标准差的位置，意味着短期内绝大多数持仓者都在亏钱，卖压来自情绪而非基本面。这种偏离通常不会持续，回归是常态。

但这句话有个致命前提——**“通常”不包括趋势行情**。

在单边下跌中，价格不会回归，它会从一个极端走到下一个极端。均值回归策略的全部风险都集中在这里：你在下跌途中接了九次都赚了小钱，第十次遇到真趋势，一次就能吞掉前面所有利润。

所以均值回归策略的盈利结构是这样的：

| 特征 | 表现 |
|---|---|
| 胜率 | 偏高（回归是常态） |
| 单笔盈利 | 偏小（目标位固定） |
| 亏损频率 | 低 |
| 单笔亏损 | **可能极大**（逆势扛单） |

这个结构决定了两件事：**止盈必须机械固定，不能贪**；**止损必须绝对可靠，不能心存侥幸**。后面所有参数设计都围绕这两条。

## 三、三个指标各管一摊

这是整套策略的设计核心：**位置、时机、容错，三件事分给三个指标，互不越界**。

| 指标 | 管什么 | 具体职责 |
|---|---|---|
| 布林带 | **位置** | 上轨下轨划出物理边界，判断“是否到了极端”；中轨是止盈目标 |
| RSI | **时机** | 判断驱动这波偏离的力量正在衰竭，还是在持续加强 |
| ATR | **容错** | 用真实波幅给止损留出缓冲，容纳插针和假突破 |

### 为什么单用任何一个都不行

**只用布林带**：价格触及下轨不等于会反弹。趋势行情中下轨会被连续跌穿几十根 K 线，每次触及都是亏损。布林带只告诉你“贵了还是便宜了”，不告诉你“现在该不该动手”。

**只用 RSI**：RSI 低于 30 只说明现在跌得很惨。但**超卖之后还有更超卖**——在单边下跌中，RSI 可以在 20 以下趴一整天。它没有位置概念，不知道这波跌到哪算到头。

**只用 ATR**：ATR 纯粹是波动率的度量，不含任何方向信息，单独用构成不了信号。

所以必须**共振**：布林带给出极端位置，RSI 确认这个位置上的力量开始转向，两条同时成立才动手。位置对了但时机没到——等着；时机看着像但位置不够极端——不做。

## 四、完整交易规则

### 入场：四个条件同时满足

| # | 条件 | 代码表达 | 解决什么问题 |
|---|---|---|---|
| 1 | 触及下轨 | `low <= bb_lower` | 位置：确认到了极端 |
| 2 | 超卖 | `rsi < 30` | 确认这波下跌确实把情绪打透支了 |
| 3 | **拐头** | `rsi > rsi_prev` | 时机：卖压开始衰竭，不是还在加速 |
| 4 | 带宽过滤 | `bb_width >= 0.015` | 排除市场过于平静时的噪音 |

三条值得单独说：

**用 `low` 而不是 `close`。** 只要盘中最低价碰到下轨就算数，不要求收盘也在下轨之下。如果改成用收盘价，那些“插针到下方又收回来”的机会全会被错过——而这恰恰是均值回归最想要的形态。

**拐头这条是整套规则的灵魂。** RSI 小于 30 只描述状态，拐头才描述变化。条件 2 和条件 3 必须成对出现：前者说“跌得很惨”，后者说“但是开始有转机了”。少了条件 3，你会在下跌还在加速时就冲进去。

**带宽过滤的作用。** 带宽的定义是 `(上轨 - 下轨) / 中轨`，衡量当前波动的绝对空间。带宽太窄时有两个问题：价格轻轻一动就触及上下轨，信号全是噪音；下轨到中轨的距离太小，扣掉双边手续费所剩无几。0.015 是按 4 小时周期估的门槛，只挡掉最死寂的那段时间。

{% note info %}
带宽过滤有代价：它同时也挡掉了布林带收窄之后即将爆发的那些机会。这是主动取舍——宁可错过，不要噪音。
{% endnote %}

### 出场：条件只有一个

**收盘价回到中轨就走。** 不加任何其他条件。

要理解这个设计，得先想清楚一件事：这个策略赚的是哪一段？是**下轨回到中轨**这一段，不是“下轨一路冲到上轨”。贪心把目标设到上轨，会让胜率从七八成掉到三四成，单笔收益增加的那点根本补不回来。

中轨是 20 周期均线，也就是市场对这波行情的**平均成本**。价格回到平均成本附近，这次偏离的修复就算完成了，剩下的涨幅跟这套逻辑没有关系。

### 止损：两层

| 层级 | 位置 | 作用 |
|---|---|---|
| 静态硬底线 | 入场价 −8% | 永久下限，不可放宽 |
| ATR 止损 | `下轨 − 1.5 × ATR` | 在硬底线之上收紧 |

{% note warning %}
这两层的关系不是你以为的那样，第五节第一个陷阱会讲清楚。
{% endnote %}

止损放在下轨**再往下一倍半 ATR** 的地方。下轨本身已经是负二倍标准差，还要在它下方留出缓冲，是因为价格触及下轨之后经常还会往下探一截。这 1.5 倍 ATR 就是留给这段“正常过冲”的余量，避免刚进场就被扫出去。

## 五、四个实现陷阱

这一节是全文最值得看的部分。规则谁都能讲，但代码跑起来和你想的不是一回事。

### 陷阱一：止损只能上移，不能下移

Freqtrade 的 `adjust_stop_loss` 内部有一道棘轮：

```python
# 止损只往上走，绝不往下走
# stop losses only walk up, never down!
if allow_refresh or (higher_stop and not self.is_short):
    self.__set_stop_loss(stop_loss_norm, stoploss)
else:
    logger.debug(f"{self.pair} - Keeping current stoploss...")
```

**止损一旦设下，就只能往上收紧，永远不能往下放宽。**

这带来一个好消息和一个要注意的地方：

**好消息**：类属性 `stoploss = -0.08` 在开仓时就把止损钉在了入场价的 92%，这道线是**永久下限**。之后 ATR 无论算出多宽的止损——哪怕下轨已经跑到 −15% 的位置——棘轮都会拒绝下移，止损永远卡在 −8% 以上。所以这个策略的**单笔最大亏损是被锁住的**。

**要注意**：如果你想“行情变了，把止损放宽一点再看看”，在这套机制下做不到。止损只能收紧，要放宽只能先平仓再重新进场。

{% note danger %}
**这里藏着一个符号陷阱。** `stoploss_from_absolute` 返回的是**正数**（表示“距离止损位还有多远”），而 `custom_stoploss` 的契约要的是**负数**（表示“亏多少触发”）。官方示例里这两个函数后面都跟着 `* -1`：

```python
return stoploss_from_absolute(...) * -1
```

直接把正数返回值拿去做比较，就变成了在两套符号域里比大小——`max(0.12, -0.08)` 永远选 0.12，那个 −8% 在比较环节**一次都赢不了**，是死代码。

好在棘轮把它兜住了，最终效果和写对了几乎一样。但这属于歪打正着，**你自己写的时候别这么干**，该加的 `* -1` 要加。

另外，当返回值恰好是 0.0 时（价格已经跌破 ATR 止损位），Freqtrade 会因为 `if stop_loss_value_custom` 的真值判断而忽略它。结果倒是对的——止损停在上一根 K 线的位置，照样触发，只是路径绕了一圈。
{% endnote %}

想要在 `custom_stoploss` 里实现真正的入场价硬止损，正确写法是直接用官方提供的 `stoploss_from_open`：

```python
# 相对入场价的 -8%，自动转成 custom_stoploss 要的口径
entry_stop = stoploss_from_open(-0.08, current_profit, is_short=False, leverage=trade.leverage)

# ATR 止损（注意 * -1 转成负数口径）
atr_stop = stoploss_from_absolute(stop_price, current_rate=current_rate,
                                  is_short=False, leverage=trade.leverage) * -1

# 取更紧者（负数域里，max 就是更紧的那个）
return max(atr_stop, entry_stop)
```

### 陷阱二：杠杆默认是交易所说了算

这个策略文件里**没有定义 `leverage()` 方法**。Freqtrade 的这个回调有两点要先搞清楚：

| 事实 | 说明 |
|---|---|
| 它只在合约模式被调用 | 现货模式下不触发，`trade.leverage` 恒为 1.0 |
| 不定义就用交易所提议值 | `proposed_leverage` 常见是 20 倍 |

所以分两种情况：

**跑现货（默认）**：不需要任何杠杆配置。`trading_mode` 默认是 `spot`，没有杠杆，−8% 就是价格跌 8%，逻辑自洽。**这个策略的设计意图本来就更接近现货**——只做多、无爆仓风险、1 倍等效。

**要跑合约**：必须在策略里把杠杆锁死：

```python
def leverage(self, *args, **kwargs) -> float:
    return 1.0
```

否则 `stoploss_from_absolute(..., leverage=trade.leverage)` 会把 −8% 的价格变动折算成 −160% 的保证金变动（20 倍时），等于价格刚跌 0.4% 就被扫损，且扫得毫无道理。

{% note info %}
**`trading_mode` 和 `margin_mode` 是 config 级的配置，不是策略类属性。** 写在策略类里不生效（也不报错，就是静静躺在那）。要改就改 `config.json`：

```json
"trading_mode": "futures",
"margin_mode": "isolated"
```
{% endnote %}

### 陷阱三：信号在你看到的价格产生，成交在下一根开盘

Freqtrade 回测的执行顺序是：

```
第 i 根 K 线满足条件  →  在第 i+1 根 K 线的开盘价成交
```

你看到的是“最低价摸到了下轨”，实际成交价是 4 小时后的那个开盘价。这中间 1%~3% 的落差，对单笔只赚 1%~2% 的均值回归策略来说，能吃掉大半利润。

这是**系统性成本，不是 bug**，回测结果里已经包含了它。真正要防的是低估它：

- 回测一定要带上真实手续费档位，别用默认的 0
- 小币种的滑点远大于主流币，别拿 BTC 的参数去套山寨
- 实盘用限价单能改善，但可能挂不上，宁可少成交也别追价

{% note info %}
这套策略的 `order_types` 入场已经设成 `limit`，这是对的。用市价单进场的均值回归策略，滑点会直接把利润吃光。
{% endnote %}

### 陷阱四：取最后一根 K 线的前视隐患

止损函数里这句：

```python
last = dataframe.iloc[-1]
```

取的是 dataframe 的最后一行。回测时 Freqtrade 逐根推进，此时最后一行就是**当前正在形成的那根 K 线**，它的收盘价还没定，但数据已经在里面了。

用当前 K 线的 `bb_lower` 去算止损位，等于用了当时还拿不到的信息。严谨的做法是取上一根**已收盘**的 K 线：

```python
closed = dataframe[dataframe["date"] < current_time]
if closed.empty:
    return hard_stop
last = closed.iloc[-1]
```

对 4 小时周期加 1.5 倍 ATR 缓冲的组合来说，这点偏差影响很小，不至于让回测结果失真。但如果要拿这套代码去做参数优化，优化器会把这点水分当成真实收益放大，选出来的参数会偏乐观。

## 六、两个设计取舍

这套策略的入场条件平平无奇，真正的判断在**它不做什么**。

### 为什么只做多

**一是不对称的风险。** 多单价格跌到最低是归零，有下限；空单价格上涨，亏损理论上没有上限。一个本来就逆势的策略，再叠加无上限风险，尾部风险没法管理。

**二是位置决定的空间。** 均值回归做多是**抄底**，做空是**摸顶**。抄底时价格已经在低位，往下的空间有限；摸顶时价格在高位，往上的空间大得多。同样的波动幅度，空单承受的反向压力普遍大于多单。

{% note info %}
只做多还有个现实好处：`can_short = False` 与现货模式天然契合，可以完全绕开杠杆、保证金、资金费率、爆仓价这一整套合约层的复杂度。对均值回归这种靠高胜率吃饭、单笔利润微薄的策略，少一层复杂度就少一层成本。
{% endnote %}

### 为什么不能用追踪止损

这是整套风控里最关键的一条判断。

趋势策略里追踪止损是好东西：盈利不断新高，止损跟着往上抬，能锁住利润。

但均值回归的盈利路径完全不同——**目标位固定在那里，价格走向目标的过程中必然反复回撤**。追踪止损会在每次回撤时把仓位扫掉：

| | 不用追踪止损 | 用了追踪止损 |
|---|---|---|
| 到达中轨 | 正常止盈 | 中途回撤时被扫出 |
| 平均持仓时间 | 完整 | 大幅缩短 |
| 实际效果 | 该赚的赚到 | **赚小亏大** |

追踪止损把“高胜率 + 固定目标”改造成了“高频率 + 小盈利”，**砍掉了利润引擎，却保留了全部亏损**。

{% note danger %}
**判断标准很简单：目标位固定的策略，别用追踪止损。** 趋势策略的风控工具直接搬到均值回归上，会让策略失效。
{% endnote %}

顺带一提，本策略的 `minimal_roi` 设成了 `{"0": 100}`（要涨一万倍才触发），等于把 Freqtrade 的 ROI 止盈整个关掉，止盈完全交给 `exit_trend`。这是对的——均值回归的出场必须由规则说了算，不能让另一个机制插一脚。

## 七、什么行情会让它亏钱

最大的软肋必须说清楚：**它没有任何趋势过滤器**。

它判断行情的方式是“价格到下轨了 + RSI 拐头了”，这两条在单边下跌中同样会成立。结果是趋势走得越远，它开仓越勤，每次都被止损打掉。

可以观察这几个信号，提前知道环境变了：

| 信号 | 含义 |
|---|---|
| 带宽从 1.5% 迅速扩大到 4% 以上 | 波动放大，趋势可能启动 |
| 价格连续多根 K 线收在上轨或下轨之外 | 这是趋势，不是震荡 |
| 连续多笔被止损 | 环境大概率已经切换 |

处理方式很朴素：**不预测，只兜底**。靠 −8% 的硬底线和 1 倍等效杠杆，让单次亏损有上限。代价是趋势来了必然亏钱，只是亏多少的问题。

{% note warning %}
**连续止损三笔以上，应该暂停这个策略，而不是继续等信号。** 均值回归策略的亏损不是均匀分布的，它会在趋势行情里集中爆发。
{% endnote %}

## 八、落地要点

### 先让它能加载

Freqtrade 加载策略是按**类名**匹配的，不是文件名。它会扫描 `user_data/strategies/` 下所有 `.py`，找出与你传的名字同名的类。

所以回测时命令里要写**类名**：

```bash
freqtrade backtesting \
  --config user_data/config.json \
  --strategy BollingerRsiAtrMeanReversion \
  --timeframe 4h \
  --timerange 20240101-20261001
```

{% note danger %}
如果写成了文件名 `Strategy02_BbRsiAtrMeanReversion`，会直接报：

```
Impossible to load Strategy 'Strategy02_BbRsiAtrMeanReversion'.
This class does not exist or contains Python code errors.
```

这个文件的文件名和类名确实不一致。**建议直接把文件改名为 `BollingerRsiAtrMeanReversion.py`**（文件头注释本来就是这么写的），省得每次都要想一下。
{% endnote %}

### config 里要确认的几项

| 配置项 | 建议值 | 说明 |
|---|---|---|
| `trading_mode` | `spot` | 合约模式需另外配杠杆 |
| `margin_mode` | `isolated` | 只在合约模式有意义 |
| `fee` | 真实档位 | 别用 0，均值回归对手续费极敏感 |
| `max_open_trades` | 3 ~ 5 | 分散到不同币种，别全押一个 |
| `stake_amount` | 单笔不超过总资金 5% | 配合 1 倍等效杠杆 |

下载数据之后才能回测：

```bash
freqtrade download-data \
  --config user_data/config.json \
  --timeframe 4h \
  --timerange 20240101-20261001
```

### 币池

选 BTC、ETH 这类主流币。小币种插针多、滑点大，均值回归最怕被插针扫损之后再涨回去。

周期 4 小时是原设定。改到 1 小时会让信号数量翻几倍，但单笔空间同步缩小、手续费占比上升，得不偿失。

{% note info %}
要 7×24 小时跑着，得有一台常开的机器。域名和服务器都可以 [点此注册腾讯云](https://curl.qcloud.com/lxNLjrln) 一站搞定，新用户有专属优惠。
{% endnote %}

## 九、还能怎么改

按优先级排：

1. **加趋势过滤器**。ADX 大于 25 时禁止开仓，或者检测带宽连续扩大就停手。这是收益最高的一改，能挡住大部分趋势行情里的无效交易。
2. **修掉符号陷阱**。用第五节给的 `stoploss_from_open` 版本替换现有的 `max()` 逻辑，让 −8% 兜底真正参与比较，而不是靠棘轮兜着。
3. **止损取上一根已收盘 K 线**。第四节给了代码，做参数优化之前必须改。
4. **带宽过滤改动态**。0.015 是按 4 小时周期估的固定值，换成该币种历史带宽的分位数会更自适应；换周期或换币种时需要重新标定。
5. **分批建仓**。触及下轨先建一半，再跌一段补一半。但这会引入马丁格尔式风险，要先算清楚爆仓边界。

## 十、最后

这套策略最值得学的，可能不是那三行入场条件，而是它**没有做的那些事**：不做空、不用追踪止损、不贪上轨、不在带宽过窄时出手。

每一条“不做”背后都有一个具体理由，而且这些理由都是从这套策略的盈利结构推出来的——目标位固定，所以不能用追踪止损；赚的是微薄的小钱，所以要挡掉噪音、要算清手续费；本来就逆势，所以不能再叠加无上限的方向风险。

一个能把回测曲线画得漂亮的策略，和一个能实盘活下来的策略，差别往往不在加了什么，而在于**知不知道什么东西不该加**。

{% note danger %}
**以上都是策略设计的逻辑拆解，不是收益承诺。** 任何参数上实盘之前，都必须用自己准备交易的币种和周期重新回测。回测赚钱、实盘亏钱是常态，对均值回归这类逆势策略尤其如此。
{% endnote %}
