这是一篇按代码逐行写的拆解，不是按想法写的。

我把一个 4 小时周期的均值回归策略原样跑了一遍回测：**457 笔交易，总收益 −70.57%，最大回撤 77.8%，胜率 39.8%**。这篇文章干两件事：前半部分把这套逻辑到底在做什么讲清楚——不美化、不补料，代码怎么写就怎么写；后半部分复盘它为什么亏，每一条原因都对应到具体某一行代码，并且都用真实数据做了对照验证。

之所以值得写，是因为**亏的原因几乎全部能在代码里读出来**。如果你只看回测曲线，只会看到一条向下的线；但读代码能知道是哪一步在漏钱，以及该动哪里。

{% note warning %}
顺带说一句：我原本以为“加趋势过滤”是首选的修复方向。做完对照实测之后这个判断被推翻了——**EMA200 过滤砍掉 96% 的信号，胜率却一点没提升**。第九节有完整数据。别跳过那一节。
{% endnote %}

## 一、这套规则在做什么

一句话：**价格跌到布林带下轨、RSI 进超卖并且开始拐头向上时做多，等收盘价回到中轨卖出，中间用「下轨再往下 1.5 个 ATR」兜住风险。**

方向上只做多，不做空；不设止盈比例，出场完全交给信号。

代码里声明的全部参数如下，一个不漏：

| 参数 | 值 | 作用 |
|---|---|---|
| `timeframe` | `4h` | 4 小时一根 K 线 |
| `can_short` | `False` | 只做多 |
| `stoploss` | `-0.08` | 静态止损 −8% |
| `use_custom_stoploss` | `True` | 启用自定义止损 |
| `minimal_roi` | `{"0": 100}` | 相当于关闭，止盈不看比例 |
| `startup_candle_count` | `100` | 预热 K 线数 |
| `process_only_new_candles` | `True` | 只在新 K 线上处理 |
| `bb_period` / `bb_std` | `20` / `2.0` | 布林带周期与标准差倍数 |
| `rsi_period` | `14` | RSI 周期 |
| `rsi_oversold` | `30` | 超卖门槛 |
| `rsi_overbought` | `70` | **定义了但代码里没用到** |
| `atr_period` | `14` | ATR 周期 |
| `atr_stop_mult` | `1.5` | 止损放在下轨下方几个 ATR |
| `min_bandwidth` | `0.015` | 布林带宽度下限过滤 |

{% note info %}
`rsi_overbought = 70` 是个遗留项。因为只做多，没有任何地方读它——砍掉空头之后它就没人用了。留着不影响运行，但读代码时容易误以为空头逻辑还在。
{% endnote %}

## 二、指标怎么算

只算四样东西，全在 `populate_indicators` 里：

```python
bb = ta.BBANDS(dataframe, timeperiod=20, nbdevup=2.0, nbdevdn=2.0)
dataframe["bb_lower"]  = bb["lowerband"]    # 中轨 − 2σ
dataframe["bb_middle"] = bb["middleband"]   # 20 期均线
dataframe["bb_upper"]  = bb["upperband"]    # 中轨 + 2σ

dataframe["bb_width"] = (bb_upper - bb_lower) / bb_middle   # = 4σ / 中轨

dataframe["rsi"]      = ta.RSI(dataframe, timeperiod=14)
dataframe["rsi_prev"] = dataframe["rsi"].shift(1)

dataframe["atr"] = ta.ATR(dataframe, timeperiod=14)
```

三个指标各管一摊，分工是这样的：

| 指标 | 回答的问题 | 在策略里的角色 |
|---|---|---|
| **布林带** | 价格现在处在什么位置 | 定边界：下轨是“便宜”的定义，中轨是“回归目标” |
| **RSI** | 动能往哪边拐 | 定时机：光便宜不够，要等它开始回头 |
| **ATR** | 一根 K 线正常波动多大 | 定容错：止损该放多远 |

`rsi_prev` 这一列是整套入场逻辑里最关键的一列——**它让“超卖”变成了“超卖且拐头”**。`bb_width` 只用于过滤，不参与判断。

## 三、入场：四个条件同时满足

```python
dataframe.loc[
    (
        (dataframe["low"] <= dataframe["bb_lower"])
        & (dataframe["rsi"] < self.rsi_oversold)
        & (dataframe["rsi"] > dataframe["rsi_prev"])
        & (dataframe["bb_width"] >= self.min_bandwidth)
        & (dataframe["volume"] > 0)
    ),
    "enter_long",
] = 1
```

逐条讲它各解决什么问题：

**1. `low <= bb_lower`：用最低价，不用收盘价**

这是有意的。收盘价跌破下轨要求当根 K 线收在极低位置，信号会少很多；用最低价意味着**只要插针碰到下轨就算**。好处是不漏掉那些瞬间砸穿又被拉回来的机会，坏处是信号数量明显变多，质量参差。

**2. `rsi < 30`：确认真的超卖**

价格到位置和动能到位置是两回事。这一条把“碰了下轨”筛成“碰了下轨且动能耗尽”。

**3. `rsi > rsi_prev`：要求拐头**

这是整个策略的灵魂。没有这一条，你会在 RSI 一路下探的过程中连续开仓——每跌一点就买一次，等于主动接飞刀。加了这一条，只在 RSI 从低点抬头的那一根才动手。

{% note warning %}
但要注意，“拐头”的门槛非常低：**只要比上一根高一点就算**。在震荡下行的行情里，RSI 在超卖区反复上下抖动，这个条件会被触发很多次。它不是趋势反转确认，只是“这一根没有继续变坏”。
{% endnote %}

**4. `bb_width >= 0.015`：带宽过滤**

意图是跳过那些布林带收得太窄、没有空间的行情。这个值在实际运行中的效果，第八节会单独说——它基本没起作用。

`volume > 0` 只是排除无成交的死 K 线，没有实际过滤意义。

## 四、出场：只有一个条件

```python
dataframe.loc[
    (
        (dataframe["close"] >= dataframe["bb_middle"])
        & (dataframe["volume"] > 0)
    ),
    "exit_long",
] = 1
```

就这么一条：**收盘价回到中轨就走**。

配合 `minimal_roi = {"0": 100}`，比例止盈等于关掉了，所以这是唯一的主动出场方式。没有最大持仓时间、没有保本退出、没有分批。

目标距离可以算出来：入场价在下轨附近，目标在中轨，两者相距 **2σ**。

## 五、止损：代码里真正的算法

这是整份代码里最值得细看的部分，因为它写出来是三行，跑起来是三层机制叠加。

```python
def custom_stoploss(self, pair, trade, current_time,
                    current_rate, current_profit, after_fill, **kwargs) -> float:
    hard_stop = -0.08
    dataframe, _ = self.dp.get_analyzed_dataframe(pair, self.timeframe)
    if dataframe is None or len(dataframe) < 1:
        return hard_stop

    last = dataframe.iloc[-1]
    stop_price = last["bb_lower"] - self.atr_stop_mult * last["atr"]

    atr_stop_pct = stoploss_from_absolute(
        stop_price,
        current_rate=current_rate,
        is_short=False,
        leverage=trade.leverage,
    )
    return max(atr_stop_pct, hard_stop)
```

表面看是「ATR 止损和 −8% 取更紧的那个」。实际执行路径是这样的：

**第一步：开仓瞬间，先按静态止损挂上**

Freqtrade 在建立交易时会先用 `stoploss` 初始化一次（`backtesting.py`）：

```python
trade.adjust_stop_loss(trade.open_rate, self.strategy.stoploss, initial=True)
```

所以初始止损价 = 入场价 × 0.92。

**第二步：每根 K 线，自定义止损被调用**

调用时传入的 `current_rate` 并不是收盘价。回测里传的是**当根 K 线的最高价**（`interface.py` 中 `current_rate=(bound or current_rate)`，多单的 `bound` 是 `high`）。

**第三步：`stoploss_from_absolute` 的返回值恒为正数**

这是最容易看错的地方。它的源码注释写得很直白：

```python
:return: Positive stop loss value relative to current price
```

也就是说，一个“下方 3%”的止损，它返回的是 `0.03`，不是 `-0.03`。

**第四步：`max()` 这行的实际结果**

```python
return max(atr_stop_pct, hard_stop)   # max(0.03, -0.08) → 0.03
```

因为 `atr_stop_pct` 恒 ≥ 0，而 `hard_stop = -0.08`，**这个 `max()` 永远返回 `atr_stop_pct`**。那句 −8% 兜底在这个比较里一次都赢不了，是死代码。

**第五步：`abs()` 把正数还原成下方止损**

真正转成价格是在 `trade_model.py` 的 `adjust_stop_loss` 里：

```python
new_loss = float(current_price * (1 - abs(stoploss / leverage)))
```

`abs()` 把 `0.03` 还原成“当前价下方 3%”。代入整个链条算下来，新的止损价恰好等于：

```
止损价 = bb_lower − 1.5 × atr
```

跟 `stop_price` 那一行完全一致——绕了一圈，结果是对的。

**第六步：棘轮，只上移不下降**

同一段源码里的判定：

```python
# stop losses only walk up, never down!
if allow_refresh or (higher_stop and not self.is_short) or ...:
```

只有新算出来的止损价**高于**旧止损，才会更新。

{% note danger %}
**把这六步合起来，实际生效的止损是：**

> **止损价 = 布林下轨 − 1.5 × ATR，且只能往上走，永远不会放宽。**

而 −8% 的静态止损只在开仓那一瞬间存在，第一次自定义止损计算就会被更紧的 ATR 止损顶掉（除非 ATR 大到 1.5×ATR 超过 8%，那只有极端行情才会发生）。
{% endnote %}

这里有个直接的后果：**入场价在下轨附近，止损在下轨下方 1.5 个 ATR**。也就是说，你判定“这里已经是极端位置”，却只允许它再极端 1.5 个 ATR。

## 六、一笔交易的完整时间线

把上面所有规则串起来，一笔典型交易长这样：

| 时点 | 发生了什么 | 依据 |
|---|---|---|
| K 线 N | 最低价插到 `bb_lower`，RSI < 30 且比上一根高，带宽达标 | 入场四条件 |
| K 线 N+1 开盘 | **按开盘价成交**（信号 `shift(1)`，见下） | `backtesting.py` |
| 成交瞬间 | 止损先挂在 入场价 × 0.92 | 静态 `stoploss` |
| K 线 N+1 起每根 | 止损重算为 `bb_lower − 1.5×ATR`，只升不降 | `custom_stoploss` |
| 若干根之后 | 收盘价 ≥ `bb_middle` → 信号 | 出场条件 |
| 再下一根开盘 | 按开盘价卖出，目标约 **+2σ** | 同上 |

{% note info %}
信号产生和成交之间隔了一根 K 线，这是 Freqtrade 刻意做的。源码里把信号列 `shift(1)` 之后再使用，注释写的是「To avoid using data from future」。所以信号基于 K 线 N 的收盘数据，成交在 K 线 N+1 的开盘价。
{% endnote %}

先说环境：Freqtrade 2026.9，币安现货，8 个主流币对（BTC / ETH / SOL / BNB / XRP / DOGE / ADA / AVAX），4 小时周期，2020-01-17 到 2026-10-01，手续费按 0.1% 单边计，最多同时持仓 3 笔。

| 总收益率 | **−70.57%**（−21170.9 USDT） |
| 年化（CAGR） | −16.67% |
| 交易笔数 | 457 |
| 胜率 | **39.8%**（182 赢 / 275 亏） |
| 平均单笔 | −0.66% |

同期市场涨了 19 倍，这套规则亏掉七成。**回撤 77.8% 且持续五年**，意味着它从 2020 年 1 月开亏之后，账户几乎再没回到过起点。

### 关键的一张表：出场方式

把 457 笔交易按出场原因拆开，问题立刻就清楚了：

| 出场方式 | 笔数 | 占比 | 胜率 | 总盈亏 |
|---|---|---|---|---|
| **止损** | 265 | 58.0% | **0%** | **−56619 USDT** |
| **信号（回到中轨）** | 189 | 41.4% | **96.3%** | **+37184 USDT** |
| 棘轮止损 | 3 | 0.7% | 0% | −1736 USDT |

**凡是走到中轨的，96.3% 都是赚的；凡是被止损的，全是亏的。**策略不是不会赚钱——它那 189 笔正常出场赚了 3.7 万——而是被 265 笔止损全部吃回去还倒贴。

这也顺带印证了第五节那个棘轮：那 3 笔 `trailing_stop_loss` 就是止损被顶上去之后触发的，说明单向收紧确实在运行。

## 八、为什么会亏：七个原因

| # | 原因 | 对应代码 | 后果 |
|---|---|---|---|
| 1 | 止损太紧，且锚在错误的参照物上 | `bb_lower - 1.5 * atr` | 趋势市里一根 K 线就扫掉 |
| 2 | 没有任何趋势过滤 | 入场条件里无方向判断 | 下跌趋势中反复接飞刀 |
| 3 | 目标在趋势市里根本到不了 | `close >= bb_middle` | 止损成了唯一出场方式 |
| 4 | 带宽过滤形同虚设，方向还反了 | `bb_width >= 0.015` | 波动越大越容易进场 |
| 5 | 信号与成交隔一根 K 线 | `shift(1)` | 成本占比过高 |
| 6 | 盈亏比只有 1 出头 | 目标 2σ vs 止损 1.5×ATR | 容错极低 |
| 7 | 棘轮 + 止损锚定下轨 | 只升不降 | 回踩第二只脚常被扫 |

### 1. 止损太紧，锚错了参照物

止损价 = 下轨 − 1.5×ATR，而入场价就在下轨。这意味着：**入场后，价格只要再往下走 1.5 个 ATR 就出局**。

问题在于，下轨本来就是统计意义上的极端位置，而价格一旦真的走出趋势，超过 1.5 个 ATR 是常态不是意外。这套规则一边用“极端”定义入场，一边用“再极端一点点”定义认输，两者是矛盾的。

### 2. 没有趋势过滤

入场条件里没有任何一句判断大方向。四个条件全部是“当前这一根长什么样”，没有一句是“现在是什么行情”。

在持续下跌里，RSI 会在 30 以下待上几十根 K 线，期间 `rsi > rsi_prev` 的“拐头”会反复出现——每一次抖动都是一次入场，每一次入场都撞上 1.5×ATR 的止损。这种连败不是运气差，是规则本身决定的。

### 3. 目标位在下跌趋势里到不了

出场只有 `close >= bb_middle` 这一条。上涨和震荡市里它很自然；但下跌趋势中，价格长期运行在中轨**下方**，中轨本身也在往下走——虽然目标在变低，可价格追不上。

结果就是：**在最容易亏钱的行情里，主动出场这条路是断的，唯一的出口是止损。**

### 4. 带宽过滤几乎不起作用，而且方向是反的

`bb_width = 4σ / 中轨`。4 小时周期下，主流币的典型带宽远大于 `0.015`（常见量级是它的好几倍），所以这个过滤**几乎从来不触发**，等于没写。

更麻烦的是它的方向：它是**下限**过滤——带宽越大越容易通过。而带宽最大的时候，恰恰是急速下跌和崩盘的时候。本该躲开的行情，它一个都没拦住；本该保留的平静行情，它也没加分。

{% note warning %}
想要过滤效果，方向应该是**上限**：带宽超过某个分位（比如近一年的 80 分位）就不做，把极端波动的行情挡在外面。或者干脆先删掉，把带宽当成一个待研究的变量，而不是一个已经调好的参数。
{% endnote %}

### 5. 信号到成交的落差，占比太高

信号基于 K 线 N 的收盘，成交在 K 线 N+1 的开盘。4 小时周期下，一根 K 线的跳空常见在 1%~2%。

而这套策略单笔目标只有 2σ，量级大约 3%。**一次跳空就能吃掉三分之二的目标。**这不是 bug，是系统成本，但对一个目标只有 3% 的策略来说，它是致命比例。

### 6. 盈亏比只有 1 出头

把数字摆在一起看：

- 目标 = 中轨 − 下轨 = **2σ**
- 止损 = 下轨往下 **1.5 × ATR**

σ（20 期标准差）和 ATR（14 期真实波幅均值）都是“一根 K 线典型波动幅度”的度量，量级相近，所以盈亏比理论上就在 1 附近。

实测印证了这一点：**平均盈利 +5.34%，平均亏损 −4.64%，盈亏比 1.15 : 1**。

按这个盈亏比反推，盈亏平衡需要 **46.5% 的胜率**。而实际胜率只有 **39.8%**——差了 6.6 个百分点。457 笔样本下这个差距不是运气问题，平均单笔 −0.66% 的期望值稳定为负。

而上面第 1、2、3 条，全都在拉低这个胜率。

### 7. 棘轮让第二只脚很难活下来

止损锚在 `bb_lower − 1.5×ATR`，而下轨是滚动的 20 期窗口。入场后如果价格先反弹再回踩，下轨往往已经抬高，止损也被顶上去了。

**同一段回踩深度，第一次能扛住，第二次就被扫。**而双底、回踩确认恰恰是均值回归最常见的形态。这个机制会系统性地把“本该等到中轨”的单子提前砍掉。

## 九、改了三处，实测结果

上面七条是读代码推出来的。推论对不对，得跑一遍才知道。我做了三个改法，各跑一次完整回测：

| 版本 | 改动 | 笔数 | 胜率 | 平均盈利 | 平均亏损 | 盈亏比 | 平衡胜率 | 止损出场 | 总盈亏 |
|---|---|---|---|---|---|---|---|---|---|
| 基准 | 原样 | 457 | 39.8% | +5.34% | −4.64% | 1.15 | 46.5% | 58.0% | **−21171** |
| 宽止损 | `atr_stop_mult` 1.5 → 3.0 | 370 | **55.4%** | +4.78% | **−7.24%** | **0.66** | 60.2% | 34.9% | −19009 |
| 趋势过滤 | 加 `close > EMA200` | 18 | 38.9% | +4.57% | −5.09% | 0.90 | 52.7% | 61.1% | −2452 |
| 两者都加 | 3.0 + EMA200 | 17 | 52.9% | +4.43% | −4.09% | 1.08 | 48.0% | 23.5% | **+621** |

### 止损宽度是个跷跷板

这是本次实测最有价值的一条。

把止损从 1.5×ATR 放宽到 3×ATR，**胜率从 39.8% 涨到 55.4%**，止损出场占比从 58% 降到 34.9%——看起来是全面改善。

但平均亏损同时从 −4.64% 扩大到 **−7.24%**，盈亏比从 1.15 掉到 **0.66**，盈亏平衡所需胜率反而从 46.5% 抬到了 **60.2%**。

缺口只是从 6.6 个百分点缩到 4.8 个百分点。**总收益从 −70.57% 变成 −63.36%，几乎没动。**

{% note danger %}
**结论：这套策略的问题不在止损宽度。**

放宽止损换来的是「赢的次数变多，但每次输得更狠」。两端同时放大，期望值原地踏步。想靠调这一个参数救回来，是不可能的。
{% endnote %}

### 趋势过滤没起到作用

我原本把趋势过滤排在第一优先级，实测**打脸了**。

加 `close > EMA200` 之后，交易笔数从 457 掉到 **18**——砍掉 96%。问题是**胜率没提升**：38.9%，跟基准的 39.8% 基本一样。

原因不难想：4 小时周期下，价格跌到布林下轨、RSI 进超卖的时候，它通常早就跌破 EMA200 了。**这两个条件本身就互斥**，同时满足的机会极少。所以这个过滤不是“筛掉坏信号”，而是“几乎把所有信号都筛掉了”。

{% note warning %}
**趋势过滤的方向是对的，但 EMA200 这把刀太狠。**要用的话，该换成描述“当前是不是趋势市”的指标（如 ADX 阈值），而不是“价格在长期均线上方”这种硬门槛。
{% endnote %}

### 那个 +621 不能当真

“趋势过滤 + 宽止损”是四组里唯一为正的（+2.07%，回撤 6.85%）。但**只有 17 笔交易**。

17 笔样本算出 52.9% 的胜率，误差范围能到 ±24 个百分点，跟抛硬币没有区别。它唯一能说明的是：**把交易频率压到极低之后，亏损确实变小了**——但这跟“策略有效”是两回事。

## 十、所以到底该动哪里

实测之后，优先级要重排：

| 优先级 | 改什么 | 实测依据 |
|---|---|---|
| **1** | **重新设计入场信号** | 宽止损把胜率提到 55.4% 仍亏，说明信号缺的不是容错，是 edge |
| **2** | 换趋势过滤的指标（ADX 之类），别用 EMA200 | EMA200 砍掉 96% 信号且胜率没提升 |
| **3** | 止损维持 1.5×ATR 附近，别往宽调 | 3×ATR 使盈亏比从 1.15 掉到 0.66 |
| **4** | 修掉 `max(atr_stop_pct, hard_stop)` 那行 | 结果碰巧对，但语义是错的 |
| **5** | 带宽过滤改成上限，或先删掉 | 第 4 条，当前几乎不起作用 |

{% note info %}
**一个更实际的判断**：如果目标是 4 小时周期上的均值回归，单笔目标只有 2σ（约 3%~5%）的话，它对**手续费和跳空**的敏感度是致命的。要么把周期拉长到日线级别、让单笔目标变大，要么就得接受这是一个对执行成本极度敏感的策略。
{% endnote %}

关于第 4 条，正确的写法是用官方提供的 `stoploss_from_open`——按**入场价**而不是当前价算，语义和代码意图才一致：

```python
from freqtrade.strategy import stoploss_from_open

# 相对入场价的固定百分比止损
return stoploss_from_open(-0.08, current_profit, is_short=False, leverage=trade.leverage)
```

另外可以加一个时间出口：用 `custom_exit` 配合 `trade.open_date` 和 `current_time` 算持仓天数，超过 N 天强制平仓。基准回测里 265 笔止损出场的平均持仓只有 17.5 小时，而盈利单平均 41 小时——**亏的走得快、赚的拿得久**，给深套的单子加个上限不会有坏处。

## 十一、跑之前要确认三件事

**1. 文件名必须和类名一致。** 类叫 `BollingerRsiAtrMeanReversion`，文件就得叫 `BollingerRsiAtrMeanReversion.py`。Freqtrade 是按类名加载策略的，文件名对不上会直接报 `Impossible to load Strategy`。

**2. 确认手续费。** 均值回归单笔只赚 2σ 左右，量级 3%。手续费不设成真实值，回测结果没有任何参考价值。

**3. 想清楚跑现货还是合约。** 这份代码没有声明杠杆，默认是现货——对它只做多的设计来说其实更自洽。要跑合约，必须显式锁 1 倍，否则会用交易所的默认值（多数是 20 倍），−8% 折算过来等于价格跌 0.4% 就扫损。

另外这类策略需要 7×24 挂着跑，机器得一直在线。用云服务器最省事，服务器和域名都可以 [点此注册腾讯云](https://curl.qcloud.com/lxNLjrln) 一站搞定。

## 十二、最后

这套规则写得并不糙。三个指标分工清楚，`rsi > rsi_prev` 那一条说明作者知道“光便宜不够，要等拐头”，用 `low` 而不是 `close` 也说明想过信号密度的问题。

但 457 笔交易跑下来，结论很硬：**−70.57%，最大回撤 77.8%，七年里只有一年是正的。**

而且它不是“差一点点”。盈亏平衡需要 46.5% 的胜率，实际 39.8%，差 6.6 个百分点——这个缺口靠调参数补不上。放宽止损能把胜率提到 55.4%，但每笔亏损同步扩大，盈亏比掉到 0.66，平衡线反而抬到 60.2%，等于白忙。

真正的问题在入场那一端：**信号本身没有区分度**。它把“跌到下轨”和“跌到下轨且会回来”当成了同一件事，而这两件事在趋势市里是完全相反的。

{% note success %}
**这次复盘给我的三条教训**

一、**先看出场原因分布，再看总收益。**总收益是一个结果，而出场原因告诉你这个结果是怎么来的。基准里 265 笔止损、189 笔信号出场，后者胜率 96.3%——光看 −70.57% 永远发现不了这个结构。

二、**胜率和盈亏比是跷跷板，别只盯着一头。**宽止损把胜率提了 15.6 个百分点，看起来大获全胜，实际总收益只从 −70.57% 变到 −63.36%。

三、**样本量太小的“改进”是幻觉。**17 笔交易跑出来的正收益，误差范围比收益本身还大，不能当作策略有效的证据。
{% endnote %}
